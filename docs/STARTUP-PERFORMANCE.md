# Windows preview startup — v1.8.1

ผู้ใช้รายงานว่าการเปิดครั้งแรกช้า โดยภาพแสดงขั้นตอน Expand-Archive ขณะแตก Node.js รุ่นนี้ปรับที่ตัวเปิดพรีวิวโดยไม่แก้ข้อมูลเว็บไซต์หรือบัญชี

| จุดที่ปรับ | พฤติกรรม |
|---|---|
| แตก Node.js | ใช้ .NET ZIP/file APIs ลดการทำงานผ่าน PowerShell provider/แถบ progress รายไฟล์ และตรวจขอบเขตปลายทางก่อนเขียน |
| ระหว่างแตกไฟล์ | ให้ GUI รับคำสั่งและตรวจยกเลิกเป็นระยะ หากผิดพลาดล้างเฉพาะ staging ที่เป็นของรอบนั้น โฟลเดอร์เดิมไม่ถูกลบ |
| ดาวน์โหลด Node.js | เก็บ ZIP ในแคชต่อผู้ใช้ key รวม SHA-256 ตรวจ bytes ที่คัดลอกอีกครั้งก่อนใช้ ถ้าแคชเสีย/เข้าไม่ได้ให้ใช้การดาวน์โหลดที่ตรวจสอบแล้วในโปรเจกต์ |
| ดาวน์โหลด npm | แคชต่อผู้ใช้พร้อม --prefer-offline; npm ci และ integrity ใน lockfile ยังคงทำงาน ไม่แชร์ node_modules |
| เปิดซ้ำ | เก็บ .runtime, node_modules และ dist ในโฟลเดอร์เดิม เพื่อข้ามการเตรียมที่มี stamp ตรงกัน |

แคชอยู่ใน `%LOCALAPPDATA%\BSIGN TECH\preview-cache` แยก `node-archives` กับ `npm-cache` มีเฉพาะไฟล์เครื่องมือและแพ็กเกจ ไม่มี .env, ฐานข้อมูล, รูปอัปโหลด หรือ initial-admin หากใช้พื้นที่นี้ไม่ได้จะ fallback เป็นพื้นที่ของโปรเจกต์ โดยไม่ต้องเปลี่ยนนโยบายระบบหรือ PATH ของเครื่อง

ครั้งแรกที่ยังไม่มีแคชต้องใช้อินเทอร์เน็ตดาวน์โหลดไฟล์ และการอัปเดตที่มีแพ็กเกจใหม่อาจต้องดาวน์โหลดเพิ่ม การลดเวลาแตก ZIP ไม่เท่ากับการลดเวลาเปิดเว็บทั้งหมดในอัตราเดียวกัน ผลวัดจริงและเครื่องที่ใช้ทดสอบจะบันทึกใน [VALIDATION.md](VALIDATION.md)

ชุดทดสอบสำหรับผู้พัฒนา/CI ใช้ `tests/windows-startup.ps1` หลังตัวเปิดเตรียม Node.js แล้ว มี `-SkipBenchmark` สำหรับข้ามการวัด ZIP จริง ชุดทดสอบใช้โฟลเดอร์ชั่วคราวและคืนค่า environment ที่แก้ไว้ ผลเวลาอยู่ใน `.runtime/logs/startup-performance.json` ผู้ใช้ทั่วไปเปิด START-WINDOWS ตามขั้นตอนเดิมได้เลย
